# Chrome Extension Multi-Environment Deployment Guide

This extension now uses WXT (Vite-powered) for all environment builds.

## Environment model

### Development
- Convex URL: `https://dazzling-badger-1.convex.cloud`
- Site URL: `https://dev.applyingmyself.com` (from shared runtime config)
- Build output: `dist/chrome-mv3-dev`

### Staging
- Convex URL: configured via shared runtime config
- Site URL: `https://dev.applyingmyself.com`
- Build output: `dist/chrome-mv3-staging`

### Production
- Convex URL: `https://oceanic-retriever-344.convex.site`
- Site URL: `https://applyingmyself.com`
- Build output: `dist/chrome-mv3`

## Build commands

```bash
bun run build:dev
bun run build:staging
bun run build:prod
```

## Packaging commands

```bash
bun run zip:staging
bun run zip:prod
# or generic production
bun run zip
```

WXT zip output is written to `apps/extension/dist/*.zip`.

## Deploy script

```bash
bun run deploy development
bun run deploy staging --zip
bun run deploy production --clean --zip
```

The deploy script now copies generated WXT zip output to `extension-<environment>.zip` in `apps/extension/` for predictable upload artifacts.

## Chrome load instructions

1. Open `chrome://extensions/`
2. Enable Developer mode
3. Load unpacked folder matching your environment output (`dist/chrome-mv3-*`)

## Pre-release checklist

- `bun run check-config`
- `bun run lint`
- `bun run type-check`
- `bun run build:prod`
- Manual smoke tests for auth/extraction/generation/history/settings

## Notes

- Manifest is generated by `wxt.config.ts`.
- Popup/background/content entrypoints are under `entrypoints/`.
- Options page surface has been removed.
